# 文档管理规范（团队共识）

项目已有文档结构时优先沿用。

## 文档放置

1. 文档按受众放置：面向使用者的说明放 `docs/`，面向维护者的约定放 `AGENTS.md` 或 `docs/`；不在仓库根目录堆积散装 md 文件（MUST NOT，根目录平铺文件可能被 agent 工具误识别为技能入口）。
2. 一份文档一个主题（SHOULD）；内容膨胀到多主题时拆分，并在原位置留指针。
3. 临时笔记、会话记录、进度日志不属于长期文档；除非用户要求，MUST NOT 将其提交为正式文档。

## 单一权威定义

4. 同一规则/事实只在一处定义，其他位置放链接（SHOULD）；发现重复表述时收敛到权威定义处，不在第二处打补丁。
5. 代码相关的描述（接口行为、配置含义）以代码和契约文档为准；文档过时不知道时，不凭记忆改写技术细节，标注"按当前实现核实"。

## 链接与同步

6. 移动或重命名文档时 MUST 同步更新所有引用链接，并检查是否有外部位置指向旧路径。
7. 修改文档描述的行为后，检查相关示例是否仍成立；不更新则标注过时。

## 写作风格

8. 中文为主，代码示例、专有名词保留英文。
9. 诚实标注来源与成熟度：不冒充外部规范原文，未验证的内容不写成已验证。
10. 修改文档的提交用 `docs:` 前缀（见 git-workflow 规则）。
