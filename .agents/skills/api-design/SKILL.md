# API 设计

先阅读现有 OpenAPI/接口文档、客户端、网关及认证约定，确定消费者和兼容要求。已有接口风格优先，不为统一外观破坏已发布契约。

1. 路径、字段、分页、状态码与错误读取 [HTTP 契约](references/http-contract.md)。
2. 写操作重试、并发修改和跨服务调用读取 [幂等与并发](references/idempotency.md)。
3. 新版本、字段演进及契约验证读取 [兼容与验证](references/evolution.md)。
4. 后端实现、前端交互和数据库设计分别按需要显式加载对应 Skill；本 Skill 是契约职责边界，不是自动依赖管理器。

输出可实现的契约：方法/路径、认证与授权、参数、请求/响应示例、失败语义、分页/幂等规则和兼容影响。项目已有 OpenAPI 时更新其源文件，不同时维护相互矛盾的多套定义。验证必须覆盖实际请求与响应，不能只检查文档能解析。
