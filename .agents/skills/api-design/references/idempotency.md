# 幂等、并发与重试

先描述重复执行的业务后果。HTTP 方法的幂等语义不代表响应必须相同；POST 如创建订单、支付应按需求定义幂等协议，而非只建议前端禁用按钮。

幂等键至少绑定调用方/租户、操作和请求摘要。相同键相同内容返回原结果或明确处理中状态；相同键不同内容返回冲突。定义有效期、可重试失败、处理中超时恢复和结果保存范围。

服务端用唯一约束、原子占位等机制处理并发，不能只“先查缓存再写”。业务写入与幂等记录需有明确一致性边界；如果跨外部服务，定义外部幂等键和恢复对账。缓存过期后是否允许再次执行需在契约中说明。

并发编辑使用版本字段或 ETag/If-Match 等项目已有协议，冲突时提示重新读取；避免无条件覆盖。区分业务状态冲突与暂时性故障，客户端不能对所有 4xx 自动重试。

对限流、暂时不可用和超时定义退避及重试预算。超时意味着结果未知，不等于操作未执行。写入重试应使用同一幂等键，并能查询最终结果。

事件交付应定义事件 ID、版本、排序需求与重复处理语义，不承诺仅靠网络传输实现 exactly-once。
