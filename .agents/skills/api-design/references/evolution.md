# 契约演进与验证

识别消费者：浏览器、移动端、第三方和内部服务的升级速度不同。新增必填请求字段、字段类型变化、错误码变化、分页变化和删除枚举值通常需要兼容策略。新增响应字段或枚举值也可能破坏严格客户端，应检查其解析行为。

优先保持向后兼容的增量变更；有意破坏兼容时定义版本、迁移窗口、弃用说明及旧版本观测。不要机械为每个接口添加 v1，也不要默认“内部接口可以随时改”。

OpenAPI 或项目已有 schema 应描述认证、字段约束、可空性、响应类型和错误。以选定规范版本表示 null，不混用不同 OpenAPI 版本语法。契约生成代码仍需要实现与业务验证。

验证覆盖：合法样例、缺失/非法字段、越权访问、分页边界、排序稳定、重复幂等键、并发版本冲突和实际错误结构。兼容变更用旧客户端/契约检查验证。示例只使用虚构数据；不存在的测试环境明确标为未验证。

跨 Skill 任务先确定契约，再分别落实前端、后端和迁移；如果实现约束迫使契约改变，回到本契约显式调整，避免各层各自发明字段或错误码。
