# 开始一个迭代

迭代 = 一个开发周期/版本，是**任务集合**的启动，不是单个任务的启动。迭代内单个任务开始时按大任务/小任务/修 bug 的对应参考处理。

## 启动清单

1. **恢复上下文**：读最近发版记录（docs/releases/）、上一迭代遗留（proposed/ 下未落地的 note、未合入分支），确认起点。
2. **收集本迭代任务**：从用户输入、需求文档、遗留 note 中汇总候选任务，逐条标注类型（大/小/bug）。
3. **排序与裁剪**：按依赖关系和价值排序；有明确时间盒的迭代 SHOULD 标出"本迭代必做"与"溢出顺延"。
4. **时间盒记录**：仅当团队真的做排期与回顾时，在 `.agents/notes/iterations/` 开一条迭代记录（可选，布局见 yx-docs notes 参考）；否则迭代清单留在会话/todo 中，不落库。
5. **逐任务启动**：按排序取第一个任务，切换到对应类型参考开始；一个任务一个分支，迭代本身不建长期分支。

## 边界

- 迭代不引入新的分支模型：任务分支从 `main` 拉，命名遵循 git-workflow 规则。
- 迭代结束时：确认所有任务分支已合入或注明原因删除；对外可感知变化汇总进 releases。
