# 开始修一个 bug

修 bug 的前提是**先定位根因**，禁止只修表象。分支用 `fix/<问题>`。

## 启动清单

1. **复现**：先构造可复现路径（步骤、输入、环境）；无法稳定复现时如实说明并先做定位，不盲改。
2. **定位根因**：读相关代码与模块文档，找到缺陷产生的真实位置；表象位置和根因位置不一致时修根因，并在提交正文中说明。
3. **开分支**：`fix/<问题简述>`，操作流程见[开分支与 worktree](branch-setup.md)。
4. **修复与回归**：最小改动修复；修复前 MUST 有一个能暴露该 bug 的验证手段（失败用例、复现脚本或手动验证步骤），修复后用它确认通过，并跑改动范围内的既有测试防回归。
5. **记录**：根因不明显或修复有取舍（多个修法选其一）时，开 `.agents/notes/proposed/bug-fix/` note 记录理由（见 yx-docs notes 参考）；简单修复不开。对外可感知的缺陷修复写入 `releases/unreleased.md`。

## 边界

- 修复中发现的无关问题不顺手修，另开任务（遵循 interaction 规则的改动最小化）。
