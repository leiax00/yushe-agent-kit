# 开始一个小任务

小任务 = 单一主题、可一次会话内完成并验证。启动成本 MUST 保持低：不为例行流程引入重资产。

## 启动清单

1. **恢复上下文**：只读与该任务直接相关的文件和最近提交；小任务不需要全量项目巡视。
2. **对齐目标**：一句话确认做什么、改哪里、怎么验证。
3. **开分支**：按改动性质用 `feat/` 或 `fix/`（操作流程见[开分支与 worktree](branch-setup.md)）；仅 typo、文档修正级别的微小改动 MAY 直接在 `main` 上提交（以 git-workflow 规则为准）。
4. **动手**：单一提交完成；完成前跑与改动范围匹配的验证命令。

## 记录取舍

小任务默认**不开 note**：决策理由不明显或方案有取舍时才开（`proposed/feature/` 等，见 yx-docs notes 参考）；绝大多数小任务的"是什么"由 git history 承载。对外可感知的变化仍写入 `releases/unreleased.md`。
