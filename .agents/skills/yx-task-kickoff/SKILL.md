# 任务启动

启动一个任务前先判断类型，再加载对应参考；类型判断依据任务本身的规模与意图，不是用户措辞的强弱。

## 任务类型判类

| 类型 | 判断特征 | 参考 |
|---|---|---|
| 迭代 | 一个开发周期/版本，含多个任务，需要排期与汇总 | [开始迭代](references/iteration.md) |
| 大任务 | 单一目标但需多步实现、跨模块或超过一两天量级，需要拆解 | [大任务](references/large-task.md) |
| 小任务 | 单一主题、可一次会话内完成并验证 | [小任务](references/small-task.md) |
| 修 bug | 修复既有缺陷，以定位根因为前提 | [修 bug](references/bugfix.md) |

判断含糊时向用户确认类型，不赌方向。一个迭代中的单个任务按大/小任务或修 bug 处理，迭代参考仅负责周期层面的启动。

各类型开分支时共用 [开分支与 worktree 操作流程](references/branch-setup.md)；类型参考只补充该类型特有的步骤，不重复操作细节。

## 通用边界

- 分支命名、提交格式、推送授权由 `.agents/rules/git-workflow.md` 注入，本 Skill 只引用不重定义。
- 会话启动的恢复上下文、对齐理解由 `.agents/rules/interaction.md` 注入。
- note 的写作与生命周期规则以 [yx-docs 决策记录](../yx-docs/references/notes.md) 为权威定义，本 Skill 只约定"何时开、开在哪"。

多类型任务（如迭代启动后立即做第一个大任务）取对应参考的并集。
