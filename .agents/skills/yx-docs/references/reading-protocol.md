# 读取协议

在项目中查找文档时的确定性流程，不靠自由发挥。

## 进入仓库

1. 先读根 README 的索引表定位目标；存在 AGENTS.md 一并读（宿主通常已注入）。
2. monorepo：仓库只有一个根 `docs/`——产品级查 `docs/product/`，跨服务技术查 `docs/tech/`，单服务内容查 `docs/services/<service>/`（内部结构与单服务 docs/ 相同）。服务定位不清时先看根 README 的仓库地图。
3. 找模块文档：服务 README 索引 → `docs/modules/<module>/README.md` → 专题文件。

## 判断文档可信度

4. 读每篇先看头部元信息（见 module-docs.md 模板）：受众不符或标注"以代码/契约源为准"的，转去读代码或契约源。
5. 文档描述与代码冲突时：代码和契约源是事实，文档是视图；以代码为准并向用户报告文档过时，MUST NOT 按过时文档"纠正"代码。
6. 注意文档中的过时标注（`> ⚠️ 过时`）：仅作历史上下文，不作为当前依据。

## 恢复决策背景

7. 想知道"为什么这样设计/为什么不用方案 B"：查 `.agents/notes/`（先 implemented/，再 rejected/——被拒绝的方案尤其防止重复踩坑），见 notes.md。
8. 想知道"版本间变了什么"：读 `docs/releases/`（先 `unreleased.md`，再具体版本文件）；模块机制的演进看模块 `history.md`；精确到 commit 的事实查 git history。

## 效率约束

9. 遵循条件加载：索引表命中哪个文档读哪个，不因"顺便"全量通读。
10. 已读且未变化的文档不重复读取。
