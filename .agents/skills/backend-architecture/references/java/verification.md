# Java 验证指南

本文件只选择证据，不重新定义架构、格式或对象规则。小改动只检查相关行为；风险增大时按下表组合，未执行项明确说明。

| 模块/目录/仓储边界 | [结构](structure.md)、[Repository](repositories-and-modules.md) | 依赖不越界；简单模块保持 AppService，复杂度需要时再按用例/能力拆分 |
| 公开 api | [api 组织](api-layout.md) | 公开类型不递归泄露 internal，消费者兼容 |
| 跨模块/服务 | [集成](integrations.md) | 入站/出站清楚；调用方仅依赖契约，远程失败按协议处理 |
| 新对象或构建变化 | [数据对象](data-objects.md)、[类型选择](record-vs-class.md) | 构造不变量、相等性、默认值、复制与消费者保持预期 |

## 按风险挑选行为案例

- 两步写入中第二步失败：事务外查询确认没有部分提交。
- 并发扣最后一份库存：最多一次成功，库存不负。
- 同幂等键并发写入：符合契约，不重复产生业务记录。
- PATCH 未传与显式 null：分别保持原值或按契约清空/拒绝。
- 跨租户/越权输入：资源不可见或拒绝，可信范围未被覆盖。
- 软删除后重建：唯一性符合实际生命周期要求。
- 远程通知失败：本地状态与重试消息可追踪，不误称全链路回滚。

纯领域行为用单元测试；绑定用实际框架链路；SQL/锁/方言需兼容数据库。Mock、编译、生成 SQL 和静态检查分别说明能证明什么，不能替代真实数据库执行。纯排版不新增镜像测试。

## 收尾

检查未提交变更与调用方，必要时干净构建，保护用户并行改动。说明实际测试、重要兼容影响与缺口；评审附位置、触发条件和影响，不为每次开发写长检查报告。
