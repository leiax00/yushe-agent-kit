# yx 项目交互约定

本 Skill 是团队协作层约定（标注为团队共识，非行业规范），不规定业务代码架构——后者由 `yx-backend-architecture`、`yx-frontend-architecture` 等领域 Skill 负责。

## 适用范围与加载时机

- 每个新会话开始、上下文压缩后、或用户要求继续之前的工作时：读取 [交互原则](references/interaction-principles.md)。
- 创建/切换/合并分支、编写提交信息、整理提交历史时：读取 [分支与提交](references/git-workflow.md)。
- 创建、修改、移动或删除文档时：读取 [文档管理](references/docs-management.md)。

多主题任务取并集（例如提交代码并更新文档），不默认全部加载。

## 核心原则（始终有效，细则见交互原则）

1. 先读后写：动手前了解项目现状与既有约定，不凭印象假设。
2. 小步推进：一次会话聚焦一个主题，改动可验证、可回退。
3. 诚实汇报：如实说明做了什么、没做什么、什么未验证；不把计划当作已完成。

## 跨领域协作

- 提交信息或文档涉及 API 契约描述时，以 `yx-api-design` 的契约为准，不在文档中另立一套定义。
- 分支保护、CI/CD 配置等仓库基础设施变更超出本 Skill 范围，需用户明确授权。

## 输出要求

会话开始时简述对当前任务的理解和计划再动手；git 操作前说明将执行的命令和影响；文档改动说明放置位置和是否更新了引用链接。
