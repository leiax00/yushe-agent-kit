# 任务收尾

任务结束先判断场景，再加载对应参考；场景判断依据任务的实际结局（完成 / 中止），不是剩余工作量。

## 场景判类

| 场景 | 判断特征 | 参考 |
|---|---|---|
| 正常完成 | 任务达成、改动已验证，准备合入 main | [正常收尾](references/finish.md) |
| 中止/不合入 | 任务跑偏、实验失败或决策放弃，分支不再合入 | [中止与不合入](references/abort.md) |
| 迭代收尾 | 一个开发周期结束，多任务清点、汇总与发版评估 | [迭代收尾](references/iteration.md) |

判断含糊时向用户确认，不赌方向。正常完成与中止共享[清理分支与 worktree](references/cleanup.md) 的操作流程；场景参考只写该场景的决策清单，不重复操作细节。

## 通用边界

- 提交格式、提交/推送双授权、合入门禁由**宿主注入的 git 工作流规则**约束（kit 仓库为 `.agents/rules/git-workflow.md`，其他项目以该项目实际注入的规则为准）；本 skill 只引用不重定义。
- note 的生命周期迁移与发版记录写法以 **yx-docs skill** 为权威定义，本 skill 只约定"何时迁、何时写"。
- 发版（版本决策、tag、渠道发布）走 **yx-release** skill；迭代收尾只做"是否发版"的评估与触发。
- 跨 skill 协作：任务启动见 **yx-task-kickoff**，两者成对使用——kickoff 开的分支由本 skill 收口。
