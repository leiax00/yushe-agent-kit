# 正常收尾

任务达成后的收尾 = 验证 → 提交 → 文档同步检查 → 合入 → 清理 → 汇报；可用性门禁在合入前一次性通过，不在每次提交上重复。

## 收尾清单

1. **验证**：跑与改动范围匹配的验证命令（构建 / 测试 / 静态检查）；失败如实报告，不带病合入。验证过的与未验证的分开记录，留给汇报。
2. **提交**：未提交改动按主题提交；`git diff --check`；不携带与任务无关的文件（本地调试产物、IDE 配置）。提交授权分级与信息格式见宿主 git 工作流规则（kit 仓库为 `.agents/rules/git-workflow.md`）。
3. **文档同步检查**（MUST 在合入前完成）：
   - 与改动相关的 README / AGENTS / docs 是否需要更新：技能表、目录树、机制描述与代码一致，不凭记忆改写技术细节；
   - 移动或改名文件的引用链接已同步（docs-management 底线）；
   - 开了 proposed note 的随合入迁入 `implemented/`，涉及模块的 `history.md` 追加演进（细则与路径见 yx-docs notes 参考）；
   - 对外可感知的变化写入 `releases/unreleased.md`（写法见 yx-docs 发版参考）。
4. **合入**：确认 main 上构建 / 测试通过（无法验证时说明原因）；合入方式按项目约定（kit 仓库默认 `--no-ff` 保留主题提交历史）；合入后按[清理分支与 worktree](cleanup.md) 执行。
5. **汇报**：提交与合入 hash、验证状态（含未验证项）、main 领先远端的笔数；推送 MUST 等用户显式要求，不链式执行。

## 边界

- squash / fixup 整理历史、直提 main 的提交，授权级别不同于任务分支 checkpoint，按 git 工作流规则逐次确认。
- 合入前发现改动偏离任务主题：拆出无关部分另起任务处理，不混在一个合入里。
