# 中止与不合入

任务跑偏、实验失败或决策放弃时的收尾。目标是 **main 零污染 + 决策留痕**，不是把半成品悄悄删掉。

## 清单

1. **定性**：与用户确认不合入，并区分两种结局——
   - **彻底放弃**：结论已定，不会再沿这个方向做；
   - **暂缓**：方向仍有价值，只是现在不做（可能重启）。
2. **决策留痕**：有取舍价值的（试过某方案且证明不可行、用户拍板否决某设计）开 `rejected` note 记录结论与理由（生命周期与写法见 yx-docs notes 参考）；纯执行跑偏、无决策含量的不留 note。
3. **分支处理**：
   - 未推送的本地分支是私有沙箱：彻底放弃 → 删除（理由落在 note 或会话汇报里，git history 不必保留）；暂缓 → 保留分支并在汇报中列出名称与前提，不让它变成无名遗留；
   - 分支上有值得重启时参考的 WIP 提交时，先提交完整再谈删除，避免"删了才发现有半成品没落地"；
   - 已推送远端的分支：删除本地不影响远端；远端去留 MUST 问用户，不擅自删。
4. **清理**：按[清理分支与 worktree](cleanup.md) 执行；worktree 同样删除，不留暂缓 worktree。
5. **汇报**：不合入的原因一句话定性、分支去向、是否留了 note。

## 边界

- 中止不是失败状态需要粉饰的事项：如实记录跑偏原因本身就是这个流程的产出之一。
- 暂缓分支不长期堆积（SHOULD）：下次迭代启动时清点，超过一个迭代周期仍无重启计划的按彻底放弃处理。
