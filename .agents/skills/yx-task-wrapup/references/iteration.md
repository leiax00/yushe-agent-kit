# 迭代收尾

迭代 = 任务集合的收尾，不是单个任务的收尾；迭代内单个任务按[正常收尾](finish.md)或[中止与不合入](abort.md)各自处理，本参考只做周期层面的清点、汇总与发版评估。

## 清单

1. **任务清点**：逐个核对本迭代的任务分支——已合入，或已按中止流程注明原因删除；列出所有仍领先远端的提交，确认没有无名遗留（暂缓分支按中止参考清点）。
2. **记录汇总**：`releases/unreleased.md` 汇总本迭代对外可感知的变化（写法权威在 yx-docs 发版参考）；`implemented/` 下 note 与代码事实同步，过时事实随本迭代修正。
3. **发版评估**：基于 unreleased 的实际变化判断是否发一版——
   - 变化已积累到值得使用者感知（新能力、行为变更、修复批次）→ 触发 **yx-release** 走发版流程；
   - 不够一版 → 留在 unreleased 积累，下个迭代再评估；
   - 评估结论（发/不发及理由）在汇报中说明，不静默跳过。
4. **迭代记录**（可选）：仅当团队真的做排期与回顾时，在迭代记录中补结论；否则不为例行流程落盘。

## 边界

- 迭代收尾不引入新分支操作：所有分支事务在单任务收尾时已处理完毕，这里只清点不补做。
- 发版本身（版本号、tag、发布渠道）不在本参考内，由 yx-release 承载。
