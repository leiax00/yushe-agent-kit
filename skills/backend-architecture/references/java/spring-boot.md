# Spring Boot 服务边界

## Web 与服务

Controller 负责绑定、格式校验、调用用例及 HTTP 映射，不编排数据库事务。Bean Validation 处理格式/长度/范围；跨对象业务不变量放在用例或领域层。认证身份和租户来自可信上下文，资源级授权必须在服务端检查。

使用项目已有的统一异常处理，区分参数错误、未认证、无权限、不存在、并发冲突和系统故障。对外错误不暴露堆栈、SQL 或内部路径。日志应保留原因与关联标识，避免多层重复记录同一异常。

## 事务

以一个需要原子性的业务用例为事务边界，确认事务管理器、数据源和调用是否经过 Spring 代理。默认代理模式下同类自调用不能触发目标方法的事务拦截；不要以 private 方法注解或新建对象调用作为事务保证。

默认回滚规则通常覆盖 RuntimeException/Error，不应假定 checked exception 自动回滚；结合项目配置明确 rollbackFor 或统一异常语义。捕获异常后正常返回可能导致提交，必须明确是否重新抛出或标记回滚。

`readOnly` 是事务/驱动优化提示，不是禁止写入的安全边界。`REQUIRES_NEW` 会独立提交且额外占用连接，仅在有意需要独立事务时使用。异步线程不能自动继承调用线程事务；异步任务需明确自己的事务边界和失败补偿。

事务内避免长时间远程调用和文件处理。读后写的库存扣减需条件更新/锁/版本控制，不靠 @Transactional 单独解决。多数据源和跨服务一致性不能直接宣称由一个注解保证。

## 配置和集成

配置按职责归组并校验必填项。环境差异通过外部配置提供，凭据不入源码。HTTP 客户端、连接池和消息消费者使用有限超时、并发和重试预算。远程 SDK 返回类型在适配器内转换，不穿透到领域。

缓存更新考虑事务提交时机和失败补偿；事务提交前删除缓存可能被旧读回填。需要可靠异步交付时采用持久化消息方案，不能仅依赖内存事件或 afterCommit 回调。

## 验证

业务规则可用纯单元测试；Web 层检查绑定、状态码和授权；事务/SQL 用真实兼容数据库做集成测试。测试中通过 Spring 代理调用服务，并在事务外验证提交/回滚结果，避免测试自身的回滚掩盖问题。

## 输入、事务时序与日志补充

绑定/显式 null/可信范围细则见 [输入契约](input-contracts.md)；业务日志与持久化审计见 [日志与审计](logging-and-audit.md)；提炼 starter 或公共技术模块时读取 [框架边界](framework-boundaries.md)。

默认以现有声明式事务覆盖用例；明确需要分段事务或动态边界时再评估程序式事务，不为轻量 DDD 统一包装事务端口/回调。入口身份校验与事务内业务资格检查各有职责，依赖当前状态的检查应位于适当事务/锁保护内。

事务拦截可能在方法体业务校验前开始资源处理，不能保证“校验失败前绝不建连”。只有需求确实约束该时序时才局部拆分，不为断言某个调用顺序新增通用框架。
