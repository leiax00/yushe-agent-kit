# Java 最小编码基线

每次 Java 变更必读。本文件是排版、参数数量建议和规范优先级的权威定义；对象构建与架构细则按任务读取，不在此展开。

## 强制格式

- 方法、构造器、compact constructor 无论多短都展开；左花括号在声明末尾，语句另起行，结束右花括号独占一行。空实现也分行；无实现的接口/抽象方法使用分号。
- if/else、for/增强 for、while/do 语句体必须有花括号。else if 可连续表达，各分支体仍展开。
- 一行一条语句、一个字段声明；4 空格缩进，不用 Tab。record 的每个组件独占一行，头部左括号后换行，右括号另起一行。
- 多步 Builder 链每次调用一行。单表达式 Lambda 可简写，语句块多行；不通过 Lambda 或嵌套三元压缩复杂控制流。

## 参数数量：团队强烈建议

SHOULD 将自有方法、接口方法和手写构造器控制在 3 个显式参数以内。这是团队共识的强烈建议，为可读性设定，不是普适硬上限或阿里巴巴手册原文。

超过 3 个时优先检查职责，将共同表达一个请求、查询条件或业务概念的参数封装为有明确名称的对象。不要机械凑成三字段分组，也不要用 Map/Object[]/任意 varargs/万能 Context 隐藏参数。

若参数没有自然聚合语义，封装反而降低可读性，或受既有/外部签名约束，可保留超过 3 个参数并简述理由，无需单独申请批准。构造注入以职责内聚为先：依赖多时检查服务职责，不把服务依赖装进参数对象，也不用字段注入、服务定位器或 Lombok 隐藏依赖。

record 隐式 canonical constructor 和 Builder 生成构造器不按手写参数个数机械评判；调用处仍应避免难读的长串位置参数。多字段构建按需读取 [构建规则](data-objects.md)。

## 可读性与范围

遵循 KISS/YAGNI：实现当前需求与必要正确性，不生成猜测性接口、模式、空目录和备用功能。名称体现业务意图；不因排版或减少参数牺牲授权、事务和失败语义。结构重构或模式选择时再读 [简洁设计](../common/clean-design.md)。

## 外部规范与团队覆盖项

以 [阿里巴巴 P3C](https://github.com/alibaba/p3c) 的适用编码规则为参考基线，尚未锁定一个完整手册版本/检查配置，不能宣称全面符合某一版阿里巴巴手册。依赖外部条款做决定时，核对项目采用版本及规则，不仅凭 Skill 概述。

项目格式要求：多行方法体、record 逐字段换行；团队强烈建议：参数不超过 3 个；新代码 Req/Resp、XxxAppService、业务名领域类型；接口与 Repository 按当前架构设计，不照搬历史手册所有 Service/DAO 接口或 Enum 后缀约定。格式/参数规则源自用户要求，不冒充外部原文。

涉及对象构建、DTO 归属或命名时读取 [数据对象](data-objects.md)；涉及架构时读取主入口对应文档。其他适用阿里巴巴规则没有因此被整体豁免，具体冲突需说明。

## 执行检查

运行现有 formatter/静态检查及相关行为测试，审阅未覆盖部分；未配置 CI 时如实说明。不要自动安装整套工具，不用简单正则替代 Java 语法检查。本 Skill 是工作指导，不等于自动强制或验证通过。
