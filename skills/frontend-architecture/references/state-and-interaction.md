# 状态、请求与交互

区分服务端缓存、URL 状态、表单草稿、组件临时状态和跨页面客户端状态。数据只保留一个权威来源，不把请求缓存再复制到全局 store。筛选和分页需要可分享/刷新时放入 URL，并校验参数。

请求键包含影响结果的筛选、分页和身份范围；账号或租户切换时避免复用旧缓存。竞态采用取消或请求序号防止旧响应覆盖新结果。组件卸载后清理监听、计时器和订阅。

提交期间禁用重复交互有助于体验，但不能代替服务端幂等。乐观更新必须能回滚，并处理多个并发修改的顺序；高风险操作优先等待服务器确认。错误保留用户输入，提供合适的重试入口，重试有副作用的请求要遵循接口协议。

表单区分初始值、草稿和提交 DTO；前端校验用于反馈，服务端仍需校验。清楚呈现字段错误和表单级错误。提供加载、空态、部分失败、离线/超时和无权限状态，是否需要全部实现由任务实际决定。

使用语义化元素、可访问名称和可见焦点；对话框处理焦点进入/退出和键盘关闭，动态错误与加载状态可被辅助技术感知。测试优先模拟真实用户操作，覆盖竞态、重复提交和权限变化，不用组件内部实现快照替代行为验证。
