# 索引、事务与并发

每个索引对应具体查询的过滤、连接或排序需求，记录读收益与写入/空间成本。复合索引顺序依据实际访问模式、等值/范围条件及排序决定，不能机械套用“选择性最高永远在前”。检查已有索引和冗余覆盖。

使用代表性数据和参数检查执行计划、扫描行数、回表与排序；EXPLAIN ANALYZE 可能真正执行语句，修改语句只在安全测试环境评估。空表计划不能代表生产表现。函数、隐式类型转换和排序规则可能影响索引使用。

大列表采用稳定排序并加入唯一键消除并列；深分页评估 keyset 游标及一致性需求。查询上限、批次大小和超时需明确。

选择隔离级别前描述需要防止的异常。事务不能自动消除丢失更新、超卖或所有幻读。条件更新检查影响行数；悲观锁保持一致加锁顺序并限制持锁时间；乐观锁冲突需要业务处理。

死锁和序列化失败可以在有限预算内重试整个可重试事务，外部副作用须去重或推迟。不要仅重试最后一条 SQL。集成验证包括并发唯一冲突、边界库存和事务回滚。
