# 数据库产品差异

以下是设计检查点，不是跨版本 SQL 保证。编写 DDL 前以实际产品、版本和配置核实。

## MySQL

确认存储引擎、字符集、排序规则、时区及 SQL mode。自增、生成列、JSON 索引和 CHECK 的支持随版本变化。唯一索引中 NULL 的行为会影响软删除活跃键方案；若用生成列表达活跃键，验证多次删除重建与组合键场景。

InnoDB 隔离与锁行为受隔离级别、索引访问路径和查询形式影响。DDL 可能隐式提交；不能假定迁移工具外层事务会回滚所有 DDL。在线 DDL 仍可能等待元数据锁，应在代表性环境测试。

## PostgreSQL

可以评估部分唯一索引表达仅活跃记录唯一，但需核对查询谓词与工具支持。唯一约束的 NULL 处理有版本与配置差异。timestamp with time zone 表达时间点，不保存原始地区时区名；业务需要原始时区时单独记录。

多数 DDL 可事务化，但并非所有操作都允许在事务块中执行；例如并发建索引需按迁移工具配置处理，失败后检查残留无效索引。大表变更、锁超时和 vacuum 影响需要独立评估。

不要把 MySQL 的自增、反引号、JSON 运算或分页语法直接复制到 PostgreSQL，反之亦然。数据库方言差异应在集成测试中验证。
